## Зачем создавать дерево построения вручную?

В классическом САПР дерево построения формируется автоматически.
Это позволяет при изменении параметров отдельных команд вызванных на
ранних шагах автоматически возпроизвести последовавшие команды.

Проблема состоит в том что не всегда такое воспроизведение возможно.
При изменении параметров раннее вызванных команд может изменится топология
модели, что, в свою очередь, может привести к недействительным ссылкам, либо же
область допустимых значений каких-либо параметров последующих команд может быть
нарушена. Решение уже этих возникших ошибок программа берет на себя. Это
приводит к неявным изменениям дерева построения, то есть программа принимает
решения в которых вы не участвовали. К примеру, вы не можете сказать, что "если
не получилось создать эту геометрию, поставь вместо неё кубик и продолжай".

Пользователи вынуждены решать эти ошибки вручную, либо полнонстью обойти
дерева построения САПР и использовать API геометрического ядра напрямую,
либо использовать API САПР с излишными уровнями абстракции.

Общим же решением задачи является полностью вручную или частично вручную определенное дерево
построения. Визуальная узловая среда является естественным для этого интерфейсом.
Потому целью данной работы явилась попытка создания такой среды, выявление
направлений развития.

## Граф

<ImageBox src="/pmc3d/graph-annotated.png">Граф в интерфейсе QtNodes.</ImageBox>


`Узел` выполняет операцию, `выходной порт` — хранит данные, `входной порт` -
лишь ссылку на выходной порт. Узел `Result` является корневым узлом и выводит
данные подключенные в свой входной порт на 3d-вьюпорт и терминал.

Результат приведенного примера, конечно, 25.

## Cписки (дерево)

Выходные порты могут хранить как отдельные значения, так и списки. Списки могут
содержать другие списки, образуют дерево данных.

Это позволяет повторно использовать построение с другими аргуметами.

<ImageBox src="/pmc3d/broadcasting-1.png"> `Range` от `5` выдает `<0, 1, 2, 3, 4>`</ImageBox>

## Вещание

Важная механика работы с такими данными, которую нужно понять, чтобы
предсказывать поведение графа. Её использует большинство реализованных узлов.
Она избавляет от явного обхода списков и согласования их элементов отдельными
узлами, упрощая построение и чтение графов.

Так, например, узел `Sqrt` определенный для одного числа, может принимать
список или целое дерево таких чисел и произвести эту опрерацию
над каждым элементом дерева. А узел `Add` определенный для двух чисел может
принимать на вход два дерева произвольных форм. Механизм вещания определяет
какие два числа передать при каждом вызове операции, сколько таких вызовов 
выполнить и как организовать результаты в выходное дерево.

### Сворачивающие порты

Некоторые операции принимают список как аргумент: ломаная `Polyline3D` строится
из списка точек, сумма `Sum` из списка чисел и т. д.
Для таких аргументов предусмотрены сворачивающие порты.

В каждом списке элементы, не являющиеся списками, передаются операции совместно.
Вложенные списки обрабатываются рекурсивно по тому же правилу. Результат
остаётся внутри исходного списка, сохраняя структуру вложенности: например,
список точек превращается в список с одной ломаной.

### Управление формой данных

Для операций над деревом данных предусмотрены отдельные узлы:

| Узел | Что делает |
| --- | --- |
| `Range` | список чисел по порядку |
| `Graft` | заворачивает каждый элемент в собственный маленький список |
| `Nest` | заворачивает всё дерево в список, как единственный элемент |
| `Flatten` | убирает вложенность, превращая список списков в один список |
| `Shift` | сдвигает список по кругу — удобно для замкнутых контуров |
| `GetItem` | берёт один элемент списка по номеру |
| `PushBack` | добавляет значение в конец списка |
| | ... |

## Граф как узел

Любой сохранённый граф можно включить в другой граф как обычный узел. Такой
узел называется функцией. Его порты объявляются специальными узлами `Input` и
`Output` внутри файла — их подписи становятся подписями портов снаружи. Входной
порт узла `Input` определяет значение по умолчание для соответствующего порта,
если при вызове оно не указано.

Функции позволяют повторно использовать построения с другими аргуметами.

### Управление потоком выполнения

Каждый узел выполняется только если вычислены данные, от которых он зависит.
Поэтому расчёт начинается с узла Result и следует по входным связям: прежде чем
выполнить операцию узла, вычисляются необходимые ему данные.

Обычно узлу нужны данные всех подключённых входов. Исключение — If: сначала
вычисляется условие, затем выбирается один из двух входов. Если условие — число,
не равное нулю, выбирается true, иначе — false. Данные второго входа не
запрашиваются, следовательно и всего подграфа.

<ImageBox src="/pmc3d/if.png">Результат: 5.</ImageBox>

### Рекурсия

Внутри графа функции можно разместить узел вызова этой же функции. Это позволяет
выразить сложное построение через повторное применение одного правила — в том
числе к результатам и отдельным частям самого построения. Это позволяет выразить
сложное построение через повторное применение одного правила — в том числе к
результатам и отдельным частям самого построения. Условие завершения задаётся
через узел `If`.

Например — геометрическая схема светового окна памирского дома.
Простой рекурсивный алгоритм по заданным точкам строит контур, находит середины
его сторон и вызывает себя с полученными точками. Каждый вызов повторяет то же
построение для нового, меньшего контура.

## Узлы ядра

Геометрические узлы предоставляют доступ к операциям C3D и используют общие
механизмы вещания и сворачивания.

| Группа | Узлы |
| --- | --- |
| Примитивы | `Point`, `Point3D`, `Vector3D`, `Axis3D`, `Placement3D` |
| Кривые | `LineSegment`, `LineSegment3D`, `Polyline3D`, `ClosePolyline`, `Contour` |
| Тела и поверхности | `ExtrusionSolid`, `LoftedShell`, `LoftedSurface`, `SweptData`, `ExtrusionValues` |
| Преобразования | `MoveSolid`, `RotateSolid`, `ScaleSolid`, `MovePolyline3D` |
